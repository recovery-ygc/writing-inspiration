# 数据库规则（references/database.md）

> 使用时机：**查库 / 写库前**必读本文件。平时不读（省 token）。
> 库位置：`D:\Obsidian\文学索引\`（Obsidian 独立库，与用户写作库完全分开，写作库零接触）

---

## 一、目录结构（三级检索，层层变小）

```
D:\Obsidian\文学索引\
├── README.md              ← 给用户看的库说明（不动）
├── index.json             ← 一级索引：主题 → 文件夹 + 同义词（超小，每次必读）
├── scenes\                ← 真实书库
│   └── 木匠\
│       ├── summary.md     ← 摘要层：一行一条（查主题就读这个）
│       ├── 001.json       ← 完整条目（含原文段），命中哪条才读哪条
│       └── 木匠.md        ← 手账（人读版，Obsidian 里翻看）
└── quotes\                ← 金句库（结构同上，字段更简）
    └── 沉默\
        ├── summary.md
        ├── 001.json
        └── 沉默.md
```

## 二、index.json 格式（一级索引，只存登记，不放条目内容）

```json
{
  "version": 1,
  "updated": "2026-08-14",
  "themes": {
    "木匠": {
      "path": "scenes/木匠",
      "files": ["001.json"],
      "aliases": ["木工", "匠人", "木作", "手艺人"]
    }
  }
}
```

- aliases 只登记**兄弟词**（同义/近义），不登记上下位宽词（如"木匠"→"手艺人"太宽，会捞爆）
- 新主题：先登记 index 再建文件夹（防同名分家）

## 三、scenes 条目字段（真实书库）

```json
{
  "theme": "木匠/手艺人",
  "entries": [
    {
      "id": "scenes-20260814-001",
      "book": "戴车匠",
      "author": "汪曾祺",
      "location": "第④-⑦段（常见阅读版）",
      "theme_tags": ["木匠", "手艺人", "劳作", "专注"],
      "excerpt": "与主题相关的一段原文，约300-400字",
      "mood": "氛围一句话（≤20字）",
      "technique": "手法一句话",
      "verified": true,
      "liked": false,
      "source": "出处链接或说明",
      "date": "2026-08-14",
      "upgraded_date": null
    }
  ]
}
```

- `verified: true` = 可定位（有原文段）；`false` = 未确证（**无 excerpt 字段**，只记 书名/作者/主题/来源/日期，不写氛围手法——没读原文写不出真实的，也不许编）
- `liked: true` = 用户亲口说"我喜欢的"（显示为【我喜欢的】）

## 四、quotes 条目字段（金句库）

```json
{
  "theme": "沉默",
  "entries": [
    {
      "id": "quotes-20260814-001",
      "quote": "真实流传的句子",
      "attribution": "冒名 | 无出处 | 待查",
      "theme_tags": ["沉默", "锋利"],
      "source": "在哪看到的（知乎/语录站/转述）",
      "liked": false,
      "date": "2026-08-14"
    }
  ]
}
```

**金句库铁律：只收"真实流传"的句子（网上/书里真的存在的），AI 绝不现编。** AI 编一句塞进去 = 造谣 + 踩纯手写底线。

## 五、写库四步（每次收录，打包触发，少一步算没写完）

1. 写完整条目（到当前批文件 001.json）
2. **自动生成摘要行**，追加到 summary.md（固定格式，见下）
3. 追加一行到主题 MD 手账
4. index 有新主题？登记（没有跳过）

**摘要行固定格式**：`《书名》｜作者｜位置｜氛围（≤20字）｜标签1/标签2｜可定位/未确证`
示例：`《戴车匠》｜汪曾祺｜第④-⑦段｜清早工坊，一个人与车床合成一体｜木匠/手艺人/劳作/专注｜可定位`

**摘要永远从完整条目生成**（先读刚收录的原文段再写摘要行），不靠记忆、不靠二手印象；摘要和完整条目同批更新，不存在"摘要过时"窗口。

## 六、去重规则（重中之重，查重查"段"不查"书"）

- **查重键 = 同书 + 同段**：同一本书、同一段 → 重复，跳过
- **同书不同段 = 不同例子 → 添加**（用户明确强调：一本书可以有多个例子，照收）
- **同书同段、只是主题词不同** → 给原条目**补挂主题标签**，不新增
- **收录前先读库检查一遍再写**

## 七、防膨胀四铁律

1. 每个条目文件上限 40 条，到点**开新文件**（001.json → 002.json），摘要层同样 40 行封顶开新
2. **永远只新建、不切分**（新建 = 写新文件 + index 加一行，不动旧数据；切分要动旧数据、可能出错）
3. 检索只读最相关的 1-2 个文件，**够用就停**
4. 主题改名/合并 = 改 index 登记 + 重命名文件夹，**一步完成**

## 八、状态升级

- 未确证 → 可定位：后来翻到原文，**重新过硬标准**（见 search.md 确证硬标准），且**一次补齐字段**（位置/原文段/氛围/手法），缺字段不允许升；记 `upgraded_date`
- 待查 → 冒名/无出处：核实反证 → 冒名；查不到明确出处 → 无出处；不核实就一直挂待查，输出时照带警告标注
- 金句 → scenes（查证真是某本书）：**迁移前先在 scenes 查重**（已有同书同段 → 合并，不迁移）；迁移 = quotes 删 + scenes 加
- **升级是捎带手，不专门开一轮联网**（除非用户明确说"把这条查一下"）

## 九、一致性规则

1. JSON 是权威；MD 手账 / summary 都是它的"人读版"，**只追加/自动生成，不手工维护**（手工改会被覆盖）
2. 主题名统一：写入前先查 index 用已有主题名
3. 万一乱了 → 用户说"重建手账" → 按 index 全量重建 MD（一次性，平时不用）
4. **原子写**：先写 `.tmp` 再替换正式文件，防"写一半"残缺
5. 路径含空格/中文（`D:\Obsidian\文学索引\`），命令/读取时用完整路径

## 十、写库后汇报（一行式，放结果末尾）

```
已收录：木匠 +1（戴车匠，可定位）｜跳过重复 0
```

- 只报元信息（哪本/什么状态/进哪个主题/跳过几条），**不重复贴条目内容**
- 纯查库命中、零动作 → **不汇报**
- 写库失败 → 如实报"写库失败 + 原因"，绝不假装成功，问要不要重试

## 十一、"我喜欢的"标记

- 只有用户开口才标（"这条我喜欢的"），AI 永不主动问、永不自动标
- 标记 = JSON 加 `liked: true` + 摘要行尾部加【我喜欢的】；取消同理
- 排序时同档匹配度下优先；可"只看我喜欢的"（免费，扫摘要层即可）

## 十二、并发与边界

- 两个会话**同时写同一主题**会互相覆盖（文件型库天性）——用户应避免同时检索同一主题；不同主题互不干扰
- 手账是生成物：用户可在 Obsidian 里**翻看**，但手写批注会被下次同步覆盖（"手账批注"是以后扩展点，第一版不做）
